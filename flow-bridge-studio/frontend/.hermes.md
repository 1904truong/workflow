# AutoWS — Project Rules for Hermes

AutoWS = `flow-bridge-studio/frontend` — React 19 + TypeScript + Vite 8 + Tailwind CSS v4.
Source of truth: `src/features/worksheet-builder/`. Git root: `C:\Users\Truong\WorkFlow`.

## Working rules (mandatory)

1. **Check first.** Before any task, list existing Skills (`skills_list`) and read Memory.
   Reuse an existing Skill and the existing layout — never duplicate.
2. **Prefer existing structure.** New code goes under the matching folder in
   `src/features/worksheet-builder/components/<feature>/` and `services/<feature>/`,
   following the naming pattern already used there (`<Feature>Editor.tsx`,
   `<Feature>Renderer.tsx`, `<Feature>Toolbar.tsx`).
3. **Learn and report.** When a multi-step workflow proves reusable, propose saving it as a Skill.
   If a Skill for that area already exists, propose **patching it** instead of creating a new one.
4. **Log failures.** When you hit an error and find the fix, record: root cause, how it was fixed,
   and the verification step that proves it.
5. **Verify before claiming done.** A workflow counts as learned only after checking real output
   (`npm run build`, `npm run lint`, or the relevant test). Report what actually ran.
6. **Ask before writing Skills.** Creating, editing, or deleting a Skill requires explicit approval.
   The runtime gate `skills.write_approval` is on — staged writes are reviewed with
   `/skills approve <id>` or `/skills reject <id>`.
7. **Ask before writing Memory.** `memory.write_approval` is on: review staged memory writes with
   `/memory approve <id>` or `/memory reject <id>`. Keep standing rules in Memory and detailed
   procedures in Skills.
8. **No unapproved product changes.** Do **not** edit product code, database schema, or deploy —
   including `git commit` / `git push`, `supabase db push`, `vercel deploy`, `gh-pages` — without
   explicit approval for that specific action. Read-only inspection, build, and lint are fine.
   Ask first for anything that touches `supabase/schema.sql`, `api/`, or deployment config.
9. **Report honestly.** State what changed, what was verified, and what remains. Never present
   fabricated output as if a tool produced it.

## Architecture (verified by reading the code)

- **3 repos under the git root `C:\Users\Truong\WorkFlow`:**
  - `flow-bridge-studio/frontend` — this app (React 19 + TS + Vite 8 + Tailwind v4). ~33k LOC TS/TSX.
  - `toby-flow-extension` — Chrome MV3 extension "Flow Bridge" (JS) + Supabase Edge Function
    `analyze-worksheet` (Gemini image planning). Holds all credentials; the web app never does.
  - `ZLayout` — separate/unrelated.
- **Data flow:** browser extension ⇄ web app via `window.postMessage` (`services/ai/extensionBridge.ts`,
  `askExtension()`). The web app holds no API keys.
- **Storage:** localStorage only — `flow_bridge_folders_v2` (folders/bài học),
  `flow_bridge_worksheets_v1`, `flow_bridge_export_history_v1`
  (`services/folderStorageService.ts`, `services/storageService.ts`).
- **Model:** `Exercise` is one wide interface in `types/index.ts`; each exercise type has its own
  optional typed payload field (`cloze?`, `tfng?`, `matchingPictures?`, …), each pointing at a
  `services/<type>/<type>Core.ts` module. **There is no discriminated union** — adding a type means
  adding a field to `Exercise` plus a core module plus a renderer branch.
- **Render:** `components/preview/ExerciseBlock.tsx` switches on which payload field is present.
- **Editor:** `components/exercises/ManualExerciseBuilderScreen.tsx` switches on `exercise.type`
  and mounts the matching `*Editor` component.
- **Smart Paste:** `services/smartPasteParser.ts` (regex/heuristic) → `smartPasteEnrich.ts`
  (`classifyByHeading`) → `smartPasteRank.ts`; optional AI override via `analyzeWorksheetWithAI()`
  (Gemini `gemini-2.5-flash` through the extension) with `planFromParser` as fallback.
- **Print:** A4 pagination is measured, not estimated — `services/pagination.ts` `packWithInfo()`.
- **Export:** DOCX = hand-built Word-compatible HTML (`services/docxExportService.ts`), PDF = browser
  print (`components/toolbar/PrintStyles.css`).

## Known gaps (verified)

### Pre-existing failures (all present at HEAD, NOT from current WIP)

- **3 TypeScript errors** (`npx tsc -b --noEmit`):
  - `components/matching-headings/MatchingHeadingsToolbar.tsx:5` — unused import `SeparatorVertical`
  - `services/ai/imagePlanCompare.ts:106` — `detectedType` widened to `ExerciseType`, but `AiExerciseType`
    (`services/ai/imagePlanSchema.ts:6-25`) omits `listening_matching`. Root cause: **two divergent type
    lists** — `ExerciseType` (19) and `AiExerciseType` (16).
  - `services/folderStorageService.ts:31` — `headerPages` may be `undefined`, but `WorksheetBranding`
    requires `'first' | 'all'`
- **2 failing tests** in `services/ai/__tests__/ai.test.ts` (133/135 pass overall):
  - "parser vs AI: bài kiểm thử khớp 4 ô A–D…" and "fallback parser: planFromParser…"

### Root cause of the 2 failing tests (reproduced)

`classifyByHeading` (`services/smartPasteEnrich.ts:33`) matches
`/match.*(?:phrasal verb|word|vocabulary|definition|meaning)|nối/i`, which fires on
`"MATCHING PICTURES & VOCABULARY"` **before** any picture branch, so
`parseWorksheetText` returns `type='matching_vocabulary'` with `imageSlots=[]` and `questions=[]`.
`planFromParser()` then produces 0 images.
`classifyExerciseType` (`smartPasteParser.ts:559`) classifies the same string as `matching_pictures`
— the two classifiers disagree. Fix direction: check `matching pictures` before `matching vocabulary`,
or exclude `vocabulary|definition|meaning` matches that also contain `picture`.

### Other bugs worth knowing (reproduced where noted)

- **Answer key is silently dropped.** `smartPasteParser.ts:480` assigns `correctAnswer` from the
  parsed `ANSWER KEY`, but `withQuestions()` (`smartPasteEnrich.ts:70-77`) rebuilds `questions` with
  `number: i+1` and **no `correctAnswer`** — so question numbers get renumbered and every answer is
  lost. Only `listening_gap_fill` keeps it (it maps `correctAnswer` itself). Reproduced: parsed
  grammar MCQ → `no=1 ans=undefined`.
- **`matching_pictures` can never be suggested.** `smartPasteRank.ts:71` `SCORERS` has no
  `matching_pictures` key → base score 0, and `classifyByHeading` never returns `matching_pictures`
  → the heading bonus never applies. Same for `listening_matching`, `listening_table_completion`,
  `matching_information`.
- **Teacher key never shows in A4 preview.** `components/preview/ExerciseBlock.tsx:34` hardcodes
  `const isTeacherKey = false;` — only the DOCX path has a teacher mode.
- **`showPlaceholders` vs `showEmptyImagePlaceholders`** are two separate flags in `PrintSettings`;
  the UI toggles the first, the renderer reads the second → the "Dotted Boxes" toggle does nothing.
- **`folderStorageService.listFolders()` can overwrite user data** — it rewrites the sample London
  folder's `exercises`/`printSettings` on every load if that folder lacks a `matching_pictures` item.
- **`localStorage.setItem` is not wrapped in try/catch** in `saveFolder`/`saveWorksheet` → a quota
  error silently loses the save (data-URL images in folders are the likely cause).
- **Dead code:** `WorksheetBuilderApp.tsx`, `components/tabs/*`, `components/editor/*`,
  `components/toolbar/BuilderToolbar.tsx`, `components/dashboard/WorksheetDashboard.tsx`,
  `services/storageService.ts` — imported by nobody. Two parallel export systems and two parallel
  storage layers exist.
- **No Supabase client in the web app.** Supabase is only reachable *through the extension*
  (`SupabaseLibrary.tsx`, `ImageStudioScreen.tsx` ask the extension). There is no `.env` and no
  `createClient` call in this package — do not assume a backend exists here. The Settings screen's
  "Supabase Database Connection" writes `fb_supabase_url`/`fb_supabase_key` that nothing reads.
- **`.doc` ≠ `.docx`.** `docxExportService.ts` emits Word-compatible HTML with a `.doc` extension and
  MIME `application/msword`; UI labels say "Word .doc" in one place and "DOCX" in another.
  Export also drops images, branding, `pageBreakBefore` and `mergeWithPrevious`.
- **Exercise-type counts are wrong in 4-5 places** (UI says 15/16, registry has **19** entries;
  `types/index.ts` union also has 19 members; `AI_EXERCISE_TYPES` in
  `services/ai/imagePlanSchema.ts:6-23` has 16 including `'other'`).
- **No `validate*` for `cloze` and `matching_pictures`.** 12 `validate*` functions exist across the
  service cores; `matching_pictures` saves unconditionally with no validation at all.
- **Massive copy-paste:** 11 near-identical `setTextStyle`/`bumpSize` pairs across the service cores
  (`matchingPicturesCore.ts:385 setTextStyle` is the original), 10 copies of `moveXItem`, 12 editors
  each with their own undo/redo stack (`pastRef`/`futureRef`/`lastPushRef`) and their own local
  `AutoTextarea`/`SectionHead`/`iconBtn` helpers. There is **no `BaseExerciseEditor` and no shared
  data hook** — only `useSplitPane`, `useAppHeaderSlot` and `EditorToolbar` are shared.
- **`exercise.type` is not authoritative.** `ManualExerciseBuilderScreen.tsx:275-286` picks the editor
  by which payload field is present (`editingExercise?.tfng !== undefined`), not by `type` — a
  `type:'tfng'` exercise with no payload opens the wrong editor. Editors also write **both** the
  legacy `questions` field and the per-type payload → duplicated state.
- **`docxExportService.ts:162-340` is a 13-deep ternary chain**; unknown types silently fall through
  to a generic `questions` renderer.
- `imagePlanSchema.ts` must stay byte-identical to
  `toby-flow-extension/supabase/functions/analyze-worksheet/schema.ts` — cross-repo sync hazard with
  no automated check.
